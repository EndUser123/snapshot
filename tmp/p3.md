## Intent Summary

cc-bifrost.ps1 is a PowerShell wrapper for Bifrost v1.5.2 that manages daemon lifecycle (start/stop/restart), routes Claude Code model requests through configured providers, and synchronizes routing rules from the SQLite DB to config.json via a clean_sync mechanism. bifrost_configured_providers.md documents the current provider catalog and routing rules as the operational record of which models route to which providers.

## Finding Synthesis

### Cluster 1: Credential Management (3 findings, shared root cause)
SEC-001 (BIFROST_API_KEY hardcoded), SEC-002 (ANTHROPIC_AUTH_TOKEN hardcoded), IO-001 (silent env fallback with hardcoded defaults), LOGIC-002 (same credentials rated HIGH by logic) — all share the same root failure: runtime credential resolution is replaced by compile-time constants.

**Evidence Strength:** Observed (lines visible in source)
**Falsifier:** If .env is present and contains both ANTHROPIC_AUTH_TOKEN and BIFROST_API_KEY, the hardcoded defaults are never used. Check: `Test-Path P:\.env` and verify it contains the actual keys.
**Wrong-Order Risk:** Removing the hardcoded defaults without ensuring .env is always present would cause the script to fail for any user who doesn't have .env configured. The .env path restriction (SEC-003 finding) must be fixed simultaneously.

### Cluster 2: Dashboard Function Scope Bug (1 finding, high impact)
LOGIC-001 (Show-BifrostDashboard $proc undefined), compliance finding (same, MEDIUM) — $proc is set only in Show-BifrostStatus but used in Show-BifrostDashboard without being set.

**Evidence Strength:** Observed — line 360 uses $proc with no prior assignment in function scope
**Falsifier:** Call `cc-bf --dashboard` immediately after `cc-bf --start` — if it reports NOT RUNNING despite the daemon being active, the bug is confirmed.
**Wrong-Order Risk:** Low — the fix (add `$proc = Get-BifrostProcess`) is self-contained and has no dependencies.

### Cluster 3: Priority Ordering Inversion (1 finding, high impact)
routes_probe.py:368 and bifrost_db.py:28 both use `ORDER BY r.priority` (ASC default). Bifrost uses higher numbers = higher priority.

**Evidence Strength:** Observed — source code confirms ORDER BY without DESC
**Falsifier:** Query the DB directly: `python3 bifrost_db.py --get-rules | ConvertFrom-Json | Select-Object -First 10 rules | Format-Table priority, name` — verify higher priority values appear first.
**Wrong-Order Risk:** Changing to DESC changes which rule fires when multiple CEL expressions match. Must verify the fix doesn't change routing for the M27/GLM-5.1/GLM-4.7 rules currently configured.

### Cluster 4: clean_sync Model Validation Gap (1 finding)
Provider name validated but model field never checked. Invalid model silently passes to config.json.

**Evidence Strength:** Observed — Test-BifrostRuleTarget only checks provider field (cc-bifrost.ps1:181-190)
**Falsifier:** Add a rule with an invalid model name to the DB, run --sync, read config.json — verify the invalid model appears without error.
**Wrong-Order Risk:** Fixing model validation first (before provider validation was already working) is safe — adding validation doesn't break existing valid rules.
